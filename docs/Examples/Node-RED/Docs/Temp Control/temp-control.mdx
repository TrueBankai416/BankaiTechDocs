This example shows a Node-RED flow that keeps a Home Assistant thermostat inside safe limits and reports on its health. All temperatures are in °F.

- **Setpoint spread**: when you change the heat or cool setpoint, the other one follows so there is always a 5 degree gap. The setpoints it sends are limited to 63–78.
- **Temperature safety**: if the room drops to 58 or below, the heat setpoints are forced to 61/66. If it reaches 82 or above, the cool setpoints are forced to 74/79.
- **Extreme setpoints**: if the cool setpoint is 60 or below, or the heat setpoint is 80 or above, the thermostat is turned off and you are notified.
- **Bypass**: a toggle that disables the spread and the extreme setpoint shutoff while you make manual changes. The temperature safety ignores it.
- **Thermostat monitoring**: notifications for the thermostat going online or erroring, a low battery, the bypass toggle changing, and (disabled in the export) filter and humidifier pad reminders.
- **Bedroom**: a subflow that runs a space heater on a schedule and shuts it off if the room gets too warm or the house is empty.

## Prerequisites

- Node-RED with the [node-red-contrib-home-assistant-websocket](https://github.com/zachowj/node-red-contrib-home-assistant-websocket) palette installed (exported with version 0.82.0) and a configured Home Assistant server connection.
- A thermostat that supports a heat and cool setpoint range, exposed as `climate.thermostat`. The export uses a Z-Wave thermostat, so the node status, battery, and reminder entities below come from the Z-Wave integration.
- A toggle helper named `input_boolean.thermostat_bypass`. Create it under **Settings → Devices & services → Helpers → Toggle**.
- **Enable Global Context Store** turned on in the Home Assistant server node, which the function uses to read the bypass state. The export has it on. The function looks the state up under `global.get('homeassistant').homeAssistant`, where `homeAssistant` is the server node's name (`Home Assistant`) in camelCase, so renaming the server node means changing that line.
- `input_boolean.home_occupied` for the Bedroom subflow. This is the occupancy switch set by the [Home Security Panel](../Home%20Security%20Panel/home-security-panel.mdx) example.
- A notify service for all devices (`notify.notify`) and one for a specific phone (`notify.mobile_app_your_phone`).

## How the thermostat logic works

The `Temp Changed` node fires on every update to `climate.thermostat`, including plain temperature readings, and sends each one straight to the `Adjust Temperature Difference` function node, which decides what to do. It has three outputs, and each one goes straight to the node that acts on it:

| Output | Goes to | Used for |
| --- | --- | --- |
| 1 | `Set Thermostat` | Keeping the 5 degree spread |
| 2 | `Notify Safety Turn-on` → `Set Thermostat` | Forcing heat or cool when the room is too cold or hot |
| 3 | `Notify Safety Turn-off` → `Turn Off Thermostat` | Extreme setpoints |

The function checks these in order and stops at the first match:

| Check | Condition | Result |
| --- | --- | --- |
| Too cold | Room at or below 58 | Set heat/cool to 61/66 (output 2) |
| Too hot | Room at or above 82 | Set heat/cool to 74/79 (output 2) |
| Bypass | `input_boolean.thermostat_bypass` is not `off` | Stop. Nothing below runs |
| Extreme setpoints | Cool setpoint at or below 60, or heat setpoint at or above 80 | Turn the thermostat off (output 3) |
| Spread | The heat or cool setpoint changed | The setpoint you didn't touch follows, keeping the 5 degree gap. Heat stays between 63 and 73 and cool between 68 and 78 (output 1) |

The bypass check sits after the two temperature checks on purpose, so the temperature safety always runs, even while the bypass is on.

The function reads the bypass state from Node-RED's global context, which the Home Assistant server node fills with every entity state. If it can't read the state, or the helper is `unavailable`, it behaves as if the bypass is on and does nothing, and it logs a warning in the unreadable case.

Nothing is sent when:

- The bypass is on, unless the room is too cold or too hot.
- Only the current temperature changed, or the setpoints already match what the function would set. This keeps the flow from repeating notifications and service calls on every update.
- The safety setpoints are already applied.
- The thermostat is already off when the extreme setpoint check matches.
- The event has no previous state, or no valid current temperature.
- The event is a late echo of the function's own last change (see below).

### Why the clamp, echo check, and bypass exist

Home Assistant can report thermostat changes late or out of order. In an earlier version of this flow, the function guessed which setpoint you had moved by comparing each event with its own previous state. A late event looked like a fresh change, the function "corrected" it, and that correction produced another event. The two setpoints kept chasing each other upward until the thermostat reached more than 500 degrees. Three safeguards now stop that:

- **Clamp**: the spread logic never sends a setpoint outside 63–78, so a runaway value is impossible even if everything else fails.
- **Echo check**: for 30 seconds after the function changes the setpoints, it ignores events that still show the setpoints from before or after that change. Those are late reports of its own change, not something you did. A real change, such as raising the setpoint by 1 degree at a time, has different values and is always processed.
- **Bypass switch**: turn on `input_boolean.thermostat_bypass` and the function stops sending the spread and extreme setpoint shutoff commands, so you can make changes by hand or stop a misbehaving flow immediately. The temperature safety still works, because it only ever sends fixed setpoints.

:::note[Why there is no rate limiter]
The original flow had a rate limiter that passed one event every 5 seconds. It was removed because it dropped events. The thermostat card in Home Assistant would show a new setpoint while the flow never acted on it, leaving Home Assistant and the thermostat out of sync. The echo check handles late events without discarding real changes.
:::

:::note[Why `Notify Safety Turn-on` blocks input overrides]
`Notify Safety Turn-on` sits between the function and `Set Thermostat`, so the message carries the new setpoints in `msg.payload.data`. Call service nodes merge that into their own data, and `notify.notify` rejects the extra `target_temp_low` and `target_temp_high` fields. **Block Input Overrides** is enabled on that node so it only sends its fixed message, and the original message still passes through to `Set Thermostat`.
:::

The function node code:

```js
// Temperatures are in °F
const SPREAD = 5;               // required gap between heat and cool setpoints
const LOW_TEMP = 58;            // room at or below this forces heating
const HIGH_TEMP = 82;           // room at or above this forces cooling
const SAFE_HEAT = { target_temp_low: 61, target_temp_high: 66 };
const SAFE_COOL = { target_temp_low: 74, target_temp_high: 79 };
const MIN_COOL_SETPOINT = 60;   // cool setpoint at or below this turns the thermostat off
const MAX_HEAT_SETPOINT = 80;   // heat setpoint at or above this turns the thermostat off
const MIN_SETPOINT = 63;        // lowest heat setpoint this flow will ever send
const MAX_SETPOINT = 78;        // highest cool setpoint this flow will ever send
const ECHO_WINDOW_MS = 30000;   // how long late events from our own change are ignored
const BYPASS_ENTITY = 'input_boolean.thermostat_bypass';

const event = msg.data && msg.data.event;
const previous = event && event.old_state && event.old_state.attributes;
const current = event && event.new_state && event.new_state.attributes;
if (!previous || !current) {
    return null;
}

const currentTemp = current.current_temperature;
const targetHeat = current.target_temp_low;
const targetCool = current.target_temp_high;
if (!Number.isFinite(currentTemp)) {
    return null;
}

// Output 2 ignores the bypass switch. Skipped when the setpoints are already
// applied, which stops repeat notifications while the room stays too hot/cold.
const forceSetpoints = (setpoints) => {
    if (targetHeat === setpoints.target_temp_low && targetCool === setpoints.target_temp_high) {
        return null;
    }
    msg.payload = { data: { ...setpoints } };
    return [null, msg, null];
};

if (currentTemp <= LOW_TEMP) {
    return forceSetpoints(SAFE_HEAT);
}
if (currentTemp >= HIGH_TEMP) {
    return forceSetpoints(SAFE_COOL);
}

// Bypass switch: stops the extreme setpoint shutoff and the spread logic below.
// The temperature safety above always runs. If the state can't be read, the
// flow is treated as bypassed.
const ha = global.get('homeassistant');
const bypass = ha?.homeAssistant?.states?.[BYPASS_ENTITY];
if (!bypass) {
    node.warn('Cannot read ' + BYPASS_ENTITY + ' from the global context');
    return null;
}
if (bypass.state !== 'off') {
    return null;
}

if (!Number.isFinite(targetHeat) || !Number.isFinite(targetCool)) {
    return null;
}

// Extreme setpoints: turn the thermostat off (unless it already is)
if (targetCool <= MIN_COOL_SETPOINT || targetHeat >= MAX_HEAT_SETPOINT) {
    if (event.new_state.state === 'off') {
        return null;
    }
    return [null, null, { payload: {} }];
}

const heatChanged = previous.target_temp_low !== targetHeat;
const coolChanged = previous.target_temp_high !== targetCool;

// Only the current temperature (or another attribute) changed
if (!heatChanged && !coolChanged) {
    return null;
}

// Lagging events from our own last change report the setpoints from before or
// after it. Acting on them would undo the change and can start a runaway loop.
// A genuine new change (such as a +1 tap) has different values and gets through.
const last = flow.get('tempControlLast');
if (last && Date.now() - last.time < ECHO_WINDOW_MS) {
    const matches = (s) => s.low === targetHeat && s.high === targetCool;
    if (matches(last.trigger) || matches(last.sent)) {
        return null;
    }
}

// The setpoint that was just moved wins; the other follows to keep the spread.
// The result is clamped so the flow can never send a runaway value.
const wantedHeat = heatChanged ? targetHeat : targetCool - SPREAD;
const newHeat = Math.min(Math.max(wantedHeat, MIN_SETPOINT), MAX_SETPOINT - SPREAD);
const newCool = newHeat + SPREAD;

// Already in sync, nothing to send
if (newHeat === targetHeat && newCool === targetCool) {
    return null;
}

flow.set('tempControlLast', {
    time: Date.now(),
    trigger: { low: targetHeat, high: targetCool },
    sent: { low: newHeat, high: newCool }
});
msg.payload = { data: { target_temp_low: newHeat, target_temp_high: newCool } };
return [msg, null, null];
```

The `Set Thermostat` and `Turn Off Thermostat` nodes target `climate.thermostat` from their own configuration, so the function doesn't need to include an entity ID.

## Thermostat monitoring

| Node | Watches | Notifies |
| --- | --- | --- |
| `Thermostat Status` | `sensor.thermostat_node_status` | "Thermostat is Online" when it reports `alive` for 1 minute, otherwise "Thermostat has Error" |
| `Battery Normal` | `sensor.hallway_thermostat_battery_level` | "Replace Thermostat Batteries" when the level is below 30 |
| `Bypass Enabled` | `input_boolean.thermostat_bypass` | "Thermostat bypass enabled" or "Thermostat bypass disabled" |
| `Filter Life Expired`, `Filter Life Reset`, `Humidifier Pad Life Expired` | Z-Wave reminder `select` entities | Filter and humidifier pad reminders. Disabled in the export. |

## Bedroom subflow

The `Bedroom` subflow controls a space heater and runs alongside the thermostat logic.

- **Schedule**: the heater turns on at 8 PM and off at 9 AM, with a notification each time.
- **Unoccupied**: the heater turns off when `input_boolean.home_occupied` has been off for 1 minute.
- **Temperature monitoring**: a `Temp` node reads the room sensor every 60 seconds. From 73 to 75 degrees, it sends a "temperature is raising" warning if the heater is on, and only when the reading moves by more than 1 degree. Above 75 degrees, it turns the heater off and sends an emergency notification if the heater was on.

## Before importing

- Create the `input_boolean.thermostat_bypass` helper first, or the function node will treat the flow as bypassed and ignore setpoint changes.
- Update the entity IDs to match your own Home Assistant. This includes `climate.thermostat`, `sensor.thermostat_node_status`, `sensor.hallway_thermostat_battery_level`, the Z-Wave reminder `select` entities, and the Bedroom entities. The ones in this export are examples.
- Replace `notify.mobile_app_your_phone` with your own mobile app notify service.
- In the `Bedroom` subflow, the heater nodes target the `bedroom` area as well as `switch.bedroom_space_heater`, so they act on every switch in that area. Remove the area, or change it, if that isn't what you want.
- The thresholds are in °F. If your thermostat uses °C, change the values at the top of the function node.
- The 63–78 limits, the 30 second echo window, and the other thresholds are constants at the top of the function node. The echo check keeps its state in flow context, so it resets when Node-RED restarts.
